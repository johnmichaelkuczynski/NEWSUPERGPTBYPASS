name: Direct transformation quality
description: Acceptance rule for transforming vague prose into direct, operational, falsifiable writing.
---

Do not accept a transformation merely because it is clearer than the input or scores better than another draft. It must replace vague operations with mechanisms, provide needed examples and success conditions, and remove puffery, hedging, and generic conclusions.

**Why:** Several prompt structures—including demonstrations, separate analysis and writing stages, and an adversarial revision stage—still regressed into polished paraphrase. Relative draft scoring can select the less-bad result while still violating the core protocol.

**How to apply:** Assess quality honestly, but never reject completed output for quality. The user explicitly requires imperfect output to be returned so Retransform can be used. Never describe a completed request as proof of quality or a detector score as guaranteed.

The user's replacement specification is T′ = N(B(E(D(T)))): decompose atomic propositions, explicitate in plain words with omitted inferential steps, burst sentence lengths, then allow repeated words and low-rate minor surface irregularities.

**Why:** The user supplied an evolutionary-psychology source and their own rewrite as calibration, explicitly calling this totally new logic. Their reported detector results are observations about those passages, not a guarantee for other text.

**How to apply:** Generalize the operation, not the example's subject or capitalization. Keep the 2× maximum and do not replace substantive qualifications or facts with artificial mistakes. Preserve the interface and never restart without permission.
